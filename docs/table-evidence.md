# Проверка источников при заполнении таблиц

`start_table_job` с параметром `document` использует исходные страницы документа вместо сжатой карточки серии.
Параметр `quality_mode` по умолчанию равен `balanced`: один раунд планирования, максимум 10 страниц
и 45 000 символов. Дополнительная модель проверяет строки с уверенностью ниже `high`; для `high`
выполняются только программные проверки цитат и справочника. Уверенная ошибка модели может пройти.
Если проверяющий оспаривает значение с существующей цитатой, `balanced` сохраняет его,
но ставит низкую уверенность и подсветку с требованием ручной проверки (`needs_review`).
В `strict` оспоренные значения удаляются. Наличие цитаты не означает, что она подтверждает вывод.
Для `deepseek-flash` и `deepseek-v4-pro` на `api.deepseek.com` режим `balanced` также явно
включает thinking с `reasoning_effort=low` и ограничивает ответ 16 384 токенами.
Параметры других API не изменяются.
`strict` включает следующие более дорогие пределы и обязательную проверку всех значений моделью.
Исполнитель ищет артикулы и может уточнять запросы и читать дополнительные страницы. Пределы одной пачки:
4 раунда планирования, 24 операции поиска/чтения, 16 страниц, 100 000 символов исходного текста.
Каждый запрос модели ограничен существующим таймаутом; общий таймаут задания пока не реализован.

Для каждого непустого результата модель должна вернуть номер прочитанной страницы и точную цитату.
Программа проверяет присутствие цитаты в переданном тексте. В режиме `strict` отдельный вызов модели оценивает, подтверждает
ли источник значение для конкретного артикула. В `strict` только явно одобренные ячейки записываются в копию.
Отсутствие ответа проверяющего не считается одобрением; `balanced` помечает такие значения для проверки.
Это дополнительная проверка той же моделью,
а не гарантия фактической правильности или независимая экспертная классификация.

Допустимые значения берутся из `outputs.allowed`; при отсутствии явного списка поддерживаются
двухколоночные листы справочников, в которых первая колонка точно совпадает с заголовком целевого поля.
Другие структуры справочников требуют явного `allowed`. Коды классификаторов нельзя обосновывать
только похожими заполненными строками: при отсутствии источника код останется пустым.

`table_job_status` возвращает `verification_issues_total`, первые 20 замечаний и `audit_file`,
а также `quote_only_cells` и `model_reviewed_cells`. `usage` содержит число HTTP-запросов,
входные/выходные/суммарные токены, сообщённые API, и число успешных ответов без usage.
Неизвестный расход не оценивается приближённо; количество запросов включает повторы.
В JSON по пути `audit_file` сохранены запросы исследования, принятые цитаты по ячейкам и отклонения.
Пустые неподтверждённые поля учитываются в обычных `unresolved` / `low_confidence`.

Без `document` сохраняется прежний режим без обязательной проверки цитат. Прогон через чат и
приём итогового файла внешней системой проверяются отдельно от прямого вызова инструмента.
