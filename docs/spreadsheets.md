# Excel и CSV/TSV в tools-server

## Общая реализация

`document_tool/spreadsheets/read.py` — один читатель для describe_table/query_table, простого read_document, архива и внешнего загрузчика Open WebUI. CSV/TSV читаются стандартным csv с сохранением строк; Excel — openpyxl, старый XLS — pandas/xlrd. `Sheet` содержит значения, формулы и исходные числа для простых нулевых форматов. Дополнительных зависимостей не установлено.

`document_tool/spreadsheets/write.py` — сохранение и проверка XLSX для fill_table и write_excel. В этой же папке operations.py отвечает за адресацию строк, фильтры, словари и редактирование; create.py создаёт книгу; export.py задаёт пути и ссылки на скачивание; jobs.py выполняет фоновые задания, evidence.py проверяет источники, classification.py подбирает коды. Старые отдельные пакеты удалены; второй реализации нет. SKILL.md доступен через document_skill(file_type="spreadsheets") и включён в ресурсы desktop-сборки; шаблон системного промпта обновлён. Существующую модель в интерфейсе нужно обновить отдельно.

## Чтение

- query_table(read_mode="values") — сохранённые значения, адреса формул и признак пустого кэша.
- read_mode="formulas" — вместо результатов формул возвращаются выражения.
- read_mode="both" — значения и отдельные выражения/saved_value/cache_missing в formula_cells.
- cache_missing означает, что в сохранённом представлении нет непустого значения; это не вычислительная проверка. Кэш может быть устаревшим, а пустой результат может быть допустимым.
- Фильтр empty не считает формулу без кэша пустой ячейкой.
- Строки CSV 00123/NA/NULL остаются строками. Поддержаны UTF-8/BOM, UTF-16 с BOM и cp1251, разделители запятая/точка с запятой/tab/pipe и многострочные кавычки. Автоопределение разделителя/кодировки не универсально для любых неоднозначных данных.
- Простые Excel-форматы 00000 сохраняются как отображаемые коды; raw_numeric_cells возвращает исходное число. Все пользовательские форматы Excel не эмулируются.
- XLS предоставляет значения без формул. Сложные array/data-table формулы XLSX требуют отдельной поддержки; обычный читатель их явно отклоняет. XLSM можно читать, запись заблокирована ради сохранности VBA.

## Редактирование и сохранение

fill_table записывает значения по номеру строки или key_column в копию источника в exports. Передавайте возвращённый path для дальнейших изменений этой копии. По умолчанию заполненные ячейки и формулы защищены. Для редактирования/очистки непустых значений нужен overwrite_existing=true; для замены формулы дополнительно replace_formulas=true. null очищает ячейку. Объединённая ячейка изменяется через верхний левый адрес.

Внутри фонового задания при skip_filled=true сохраняются уже заполненные поля частично заполненных строк. Учёт завершения учитывает сохранённые поля. skip_filled=false разрешает переобработку обычных значений; формулы остаются защищёнными.

write_excel создаёт новый XLSX, включая выражения формул в строках с =. При повторном имени выбирается свободное имя. Прямая запись CSV/TSV и XLS на этом этапе не добавлялась.

Перед публикацией сохраняется временная книга, которая повторно открывается. Сравниваются значения, типы, формулы, стили ячеек, примечания/гиперссылки, листы, объединения, основные размеры строк/колонок, фильтры, Data Validation, именованные диапазоны и число диаграмм/изображений. Это проверка выбранных свойств сериализации, не полная визуальная/побайтовая проверка всех объектов Excel и не проверка правильности формул. При расхождении существующий выходной файл сохраняется. При нулевой записи книга не пересохраняется.

Формулы не пересчитываются: openpyxl не является вычислительным движком. После редактирования кэш результатов может отсутствовать. verification возвращает это предупреждение. Для расчётов нужен отдельный этап в Excel/совместимом движке; автоматический LibreOffice-пересчёт пока не добавлен. allowed_values — явный словарь, не полный исполнитель ограничений Excel Data Validation.

## Проверки

50 локальных тестов: прежние PDF/табличные сценарии, CSV/TSV в нескольких кодировках, режимы формул, защита ячеек, редактирование и очистка, создание XLSX, сохранение свойств шаблона, отказ при повреждении временной книги и сохранение заполненных полей/формул в фоновых заданиях. Cloud API для этого этапа не вызывались.

Проверена запись одной ячейки в отдельную копию реального шаблона Честного знака: книга повторно открылась, проверено 2507 ячеек, SHA-256 исходного файла не изменился. Это не новая проверка точности товарных описаний или классификационных кодов.

Справочник ОКПД2 остаётся единственным файлом app/reference_data/okpd2.json; модуль classification.py обращается к нему по новому относительному пути. Названия публичных HTTP-инструментов и параметры запросов сохранены.
