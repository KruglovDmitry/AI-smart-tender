## B. Заметки из прогонов — сделано 26.10 (`tender-agent/src/tender_agent/sites/learning.py`), проверка 27.10

Как устроено:
- После каждого прогона (в фоне, ответ не ждёт) модель агента получает сжатый трейс — шаги на страницах этой
  площадки с рассуждениями и итогами, — текущую заметку и кандидатов. Возвращает `confirm` / `refute` / `new`
  (до 3 новых выводов, одно предложение, только о поведении сайта). Ответ модели — в трейсе прогона `notes.json`.
- Кандидаты: `<data_dir>/_agent/sites/candidates/<домен>.json`. Новый вывод из удачного прогона сразу получает
  одно подтверждение; из неудачного (таймаут, лимит шагов, сбой) — ни одного.
- Действующим кандидат становится после 2 подтверждений удачными прогонами; модель видит его после заметки
  с пометкой «(авто дата)». `kind: remove` — пункт заметки, который прогоны признали устаревшим: модель его
  больше не видит.
- Действующий возвращается в кандидаты (подтверждения обнуляются) после 2 плохих прогонов подряд:
  таймаут/лимит/сбой, опровержение моделью или в 1,5 раза дольше медианы подтверждавших прогонов.
- Выключатель: `TENDER_AGENT_NOTES_LEARNING=false`. Пункт 4 (ручное редактирование в скрытом разделе панели) — не сделан,
  пока правим JSON кандидатов руками.

Проверка на трейсах 26.10 (Фабрикант, 2 прогона): из неудачного прогона — 3 вывода без подтверждений
(вкладка «Все» не читается, документы на вкладке «Документы», чекбокс статуса перекрыт); удачный прогон подтвердил
два из них, опроверг первый и добавил «попап статуса не закрывается сам».

### Исходный план B

Пользователь этого не видит и ничего не подтверждает: это внутренний механизм.

1. После прогона модель по трейсу предлагает дополнения к заметке (что сработало, ловушки).
   Они попадают в кандидаты (`_agent/sites/candidates/`), а не в заметку.
2. Кандидат становится заметкой автоматически, когда тот же вывод подтвердился в 2–3 удачных прогонах.
   Если с заметкой прогоны стали хуже (больше шагов, таймауты), она возвращается в кандидаты.
3. Мы собираем кандидатов с пробных установок и лучшие включаем в базовые заметки следующей сборки.
4. Ручное редактирование — только в скрытом разделе панели для нас; клиент его не видит.

## C. Кэш действий (после B)

- Удачная последовательность на площадке (закрыть обучение, сортировка, фильтр) запоминается по домену и этапу
  и в следующий раз повторяется без вызова модели.
- Элемент не найден или страница не та — управление возвращается модели, кэш обновляется по новому удачному шагу.
- Замерить экономию: вызовы модели, токены, время на площадку.
