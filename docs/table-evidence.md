# Проверка источников при заполнении таблиц

`start_table_job` с параметром `document` использует исходные страницы документа вместо сжатой карточки серии.
Исполнитель ищет артикулы и может уточнять запросы и читать дополнительные страницы. Пределы одной пачки:
4 раунда планирования, 24 операции поиска/чтения, 16 страниц, 100 000 символов исходного текста.
Каждый запрос модели ограничен существующим таймаутом; общий таймаут задания пока не реализован.

Для каждого непустого результата модель должна вернуть номер прочитанной страницы и точную цитату.
Программа проверяет присутствие цитаты в переданном тексте. Отдельный вызов модели оценивает, подтверждает
ли источник значение для конкретного артикула. Только явно одобренные ячейки записываются в копию.
Отсутствие ответа проверяющего не считается одобрением. Это дополнительная проверка той же моделью,
а не гарантия фактической правильности или независимая экспертная классификация.

Допустимые значения берутся из `outputs.allowed`; при отсутствии явного списка поддерживаются
двухколоночные листы справочников, в которых первая колонка точно совпадает с заголовком целевого поля.
Другие структуры справочников требуют явного `allowed`. Коды классификаторов нельзя обосновывать
только похожими заполненными строками: при отсутствии источника код останется пустым.

`table_job_status` возвращает `verification_issues_total`, первые 20 замечаний и `audit_file`.
В JSON по пути `audit_file` сохранены запросы исследования, принятые цитаты по ячейкам и отклонения.
Пустые неподтверждённые поля учитываются в обычных `unresolved` / `low_confidence`.

Без `document` сохраняется прежний режим без обязательной проверки цитат. Прогон через чат и
приём итогового файла внешней системой проверяются отдельно от прямого вызова инструмента.
