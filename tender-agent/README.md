# Браузерный агент поиска закупок

Отдельный пакет `tender_agent`. Он получает задание на естественном языке, открывает площадку в Playwright, ищет закупки и возвращает структурированный результат.

В основном проекте агент работает отдельным контейнером `tender-agent` и отдаёт Open WebUI инструмент `POST /search_tenders` на порту 8010.

## Как работает

Цикл как у browser-use: наблюдение → решение модели → действие → проверка (`agent/loop.py`). Один и тот же цикл работает на выдаче и на карточке закупки, меняются только цель и `extract`.

- **Наблюдение** (`browser/snapshot.py`): адрес, видимый текст страницы и пронумерованные интерактивные элементы. Никаких выводов вроде «это поле поиска» — их делает модель.
- **Решение**: модель получает цель, историю своих шагов с итогами и снимок и выбирает одно действие: `click`, `fill`, `scroll`, `go_back`, `goto` (тот же сайт), `extract`, `done`, `ask_user`, `vision`.
- **Действие и проверка**: код выполняет действие, снимает страницу заново и пишет в историю, изменилась ли она, куда перешли, была ли ошибка.
- **extract** на выдаче: модель возвращает записи дословными цитатами и номер ссылки на карточку; принимаются только записи, чьё название есть в тексте страницы, а ссылка — среди ссылок страницы (`tenders/reading.py`).
- **Зрение** (ai_vision): когда модель просит его сама или два действия подряд не изменили страницу.
- **Карточки** (`agent/cards.py`): каждая найденная закупка открывается в своей вкладке (до 5 одновременно) со своим бюджетом времени. Цель — прочитать поля и документы; если файлов нет, модель сама ищет вкладку «Документы». `extract` на карточке принимает цитаты, которых нет на странице, и элементы, которых нет в снимке, не принимает (`tenders/card_reading.py`).
- **Скачивание**: включается словом «скачай» в задании или флагом `download` в `POST /search_tenders` (флаг сильнее текста). `TENDER_AGENT_DOWNLOADS=false` выключает скачивание совсем. Файлы качаются сразу при `extract` на карточке.
- Памяти о площадках пока нет: каждая площадка — новая.
- Не входит в аккаунт и не обходит CAPTCHA: модель отвечает `ask_user`, задача получает статус `needs_user`.

## Установка

Нужен Python 3.10+. Образ tools-server собран на 3.10, локально пакет проверялся на 3.12.

```powershell
cd tender-agent
py -3 -m pip install -e ".[dev]"
py -3 -m playwright install chromium
```

Секреты задаются переменными окружения, образец — в `.env.example`. Файл `.env` в пакет не читается, пока его явно не подхватит окружение процесса.

## Запуск

```powershell
py -3 -m tender_agent "С площадки https://example.com верни последние пять закупок по ключевому слову ""сервер"""
```

Команда печатает JSON со статусом `completed`, `partial`, `needs_user` или `failed`.

Локальные и внутренние адреса отклоняются. Пустой `TENDER_AGENT_ALLOWED_HOSTS` разрешает публичные хосты. Непустой список ограничивает переходы этими доменами.

## Проверка

```powershell
py -3 -m pytest
```

Основной набор ходит только на локальные HTML-фикстуры через `tenders.example.test`. Внешние площадки в него не входят.

## Настройки по умолчанию

| Переменная | Значение |
| --- | --- |
| `TENDER_AGENT_MAX_ACTIONS` | 40 (шагов цикла) |
| `TENDER_AGENT_TIMEOUT_SECONDS` | 300 (время зрения не входит) |
| `TENDER_AGENT_MAX_PAGES` | 5 |
| `TENDER_AGENT_DEFAULT_LIMIT` | 5 |
| `TENDER_AGENT_CARD_TIMEOUT_SECONDS` | 90 (на одну карточку, со зрением) |
| `TENDER_AGENT_CARD_MAX_STEPS` | 10 |
| `TENDER_AGENT_DOWNLOADS` | true (false — не качать никогда) |

Каталог данных — `data/tenders` в корне репозитория, тот же, что у остального проекта. Журнал запусков лежит в `data/tenders/_agent`, скачанные файлы — в `data/tenders/_browser`. Папки с префиксом `_` дашборд не показывает как закупки. Путь в `.env` считается от корня репозитория.

## Ограничения

Без настроенной модели агент не работает. Совпадение с ключевым словом — это вхождение в название: запись без слова в названии остаётся с пометкой `needs_review`, а не отбрасывается.

## База найденных закупок

Всё, что агент вернул, сохраняется в базу. В Docker это Postgres (сервис `postgres`, контейнер `tender-postgres`), его же будет читать дашборд. При запуске из CLI без `TENDER_AGENT_DB_URL` используется SQLite `data/tenders/_agent/agent.sqlite3`.

| Таблица | Что внутри |
| --- | --- |
| `tenders` | Площадка, номер, название, заказчик, цена, валюта, даты публикации и окончания подачи, статус, ссылка, `sources` (откуда взято каждое поле), `first_seen`, `last_seen`, `seen_count`. Ключ — площадка + номер (без номера — ссылка). Пустые поля нового прогона не затирают известные |
| `tender_documents` | Название и ссылка документа, путь к скачанному файлу и его размер |
| `search_runs` | Прогон: площадка, запрос, текст задания, статус, число записей и новых, ошибки, статистика, папка трейса |
| `run_tenders` | Какие закупки вернул прогон, в каком порядке и были ли они новыми |

В ответе агента у каждой закупки есть `is_new`, в `stats` — `new_tenders` и `db_run_id`. Чтение: `GET /tenders?platform=zakupki.gov.ru&q=сервер&since=2026-10-13&limit=50`.

Загрузить в базу результаты прогонов, сделанных до её появления (по трейсам):

```powershell
docker exec tender-agent python -m tender_agent.storage.backfill
```

Подключение с этого ПК (DBeaver, psql): `localhost:5432`, база, пользователь и пароль — `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` из `.env`.

## Трейсы прогонов и разбор ошибок

Каждый прогон пишет папку `data/tenders/_agent/runs/<время>-<площадка>/`:

| Файл | Что внутри |
| --- | --- |
| `task.json` | Текст задания и разобранный `TaskSpec` |
| `steps.jsonl` | Строка на шаг: адрес, заголовок, сколько элементов и текста, решение модели (`thought`, `tool`, `ref`, `text`…), итог шага, как он записан в историю модели (`note`), изменилась ли страница |
| `llm.jsonl` | Вызовы модели: `next_action` (цель, история, снимок страницы) и `read_results` (текст выдачи и ссылки) — что ушло и сырой ответ |
| `step_XX.png`, `page_XX.txt` | Скриншот и текст страницы на шагах с ошибкой (`TENDER_AGENT_TRACE_SCREENSHOTS=all` — на каждом шаге) |
| `result.json` | Итоговый ответ агента |
| `vision/` | Трейсы vision-шагов ai_vision: скриншоты с отметкой клика, решения планировщика |

Общий `data/tenders/_agent/runs/index.jsonl` хранит строку на прогон (площадка, задание, статус, число записей, ошибки, путь к трейсу). Сводка по площадкам:

```powershell
py -3 -m tender_agent.observability.report            # таблица по площадкам
py -3 -m tender_agent.observability.report --failed   # неудачные прогоны с ошибками и путями к трейсам
```

В контейнере: `docker exec tender-agent python -m tender_agent.observability.report --failed`.

Трейс отключается переменной `TENDER_AGENT_TRACE=false`. Ключи API в трейс не попадают, но текст страниц и ответы модели попадают целиком.

## Запасной шаг по скриншотам (ai_vision)

Если модель по DOM не справляется, цикл передаёт вкладку агенту из репозитория [AI-vision](../../AI-vision): Qwen-VL решает, что делать, UI-TARS даёт координаты клика. Это происходит, когда модель сама выбирает `vision` (нужного элемента нет среди пронумерованных) или два действия подряд не изменили страницу. Итог зрения попадает в историю модели, и цикл продолжается. Данные зрение не читает.

```powershell
py -3 -m pip install -e ..\..\AI-vision
$env:TENDER_AGENT_VISION_ENABLED="true"
```

| Переменная | Значение |
| --- | --- |
| `TENDER_AGENT_VISION_ENABLED` | `false` |
| `TENDER_AGENT_VISION_MAX_CALLS` | 2 |
| `TENDER_AGENT_VISION_MAX_STEPS` | 10 |

Время vision-шага не входит в `TENDER_AGENT_TIMEOUT_SECONDS`. В `stats.vision_calls` видно, сколько раз он вызывался, в `steps.jsonl` — его итог, в `vision/` — скриншоты.
