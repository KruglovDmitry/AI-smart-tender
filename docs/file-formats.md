# Чтение остальных форматов в tools-server

## Общий маршрут

extract.py остался диспетчером простого извлечения. Он определяет настоящий формат и вызывает единственный обработчик из папки формата. Старые реализации DOC/RTF/OpenDocument и архивов перенесены, а не скопированы. Индекс, поиск, ограничение контекста и продолжение находятся в document_index. Версия индекса 6 автоматически перестраивает прежние записи.

read_file(mode=auto) использует этот общий индекс. Небольшой документ отдаётся содержимым, большой — оглавлением. Для полного чтения mode=full и next_cursor.start_part/text_offset при неизменных параметрах. Номера parts имеют смысл только вместе с page_unit: pdf_page, logical_part, slide, image_frame или archive_manifest_part. Ни один из специализированных обработчиков не реализует свой отдельный цикл продолжения. Excel по-прежнему следует читать через describe_table/query_table.

Вызови document_skill для нужного формата: presentations, images, text, archives или legacy. Эти ресурсы включены в desktop/build_tools_exe.ps1. Шаблон промпта дополнен; существующая модель Open WebUI не изменяется автоматически.

## PPTX и старый PPT

document_tool/presentations/read.py использует python-pptx: объекты слайдов, вложенные группы, абзацы/уровни, таблицы с объединениями, заметки и image IDs. Результат одного элемента индекса — один слайд. Табличный текст и заметки доступны общему поиску. Порядок объектов — порядок XML; координаты групп локальные EMU. Это не восстановленная визуальная вёрстка. Сохранённые ряды диаграмм могут быть извлечены частично; категории/оси и сложные композиции требуют просмотра.

read_presentation читает слайды. view_presentation_image смотрит одну встроенную растровую картинку через Qwen-VL. view_slide рендерит копию файла в PDF через LibreOffice и использует существующий PDF-viewer. Он нужен для композиции, диаграмм и SmartArt; результат зависит от шрифтов/конвертера. Без LibreOffice встроенные картинки доступны, полный слайд — нет. PPT 97–2003 сначала конвертируется в PPTX установленным LibreOffice. Создание/редактирование презентаций не добавлялись; анимации/видео не воспроизводятся. Объекты из мастеров/фонов не обещаются как полный текст.

API объектов/групп и ограничение заметок сверены с [python-pptx shapes](https://python-pptx.readthedocs.io/en/latest/api/shapes.html) и [slides](https://python-pptx.readthedocs.io/en/latest/api/slides.html).

## Изображения

document_tool/images/read.py индексирует кадры PNG/JPEG/TIFF/BMP/WebP/GIF через Pillow. read_image без vision возвращает только метаданные и явно не подтверждает чтение пикселей. view_image читает выбранный кадр или bbox в ориентированных пикселях. ocr_image запускает локальный RapidOCR через тот же движок, что используется у PDF. OCR-результат возвращается отдельно и не подменяет индекс метаданных.

document_tool/raster.py общий для DOCX, презентаций и отдельных изображений: EXIF orientation, белая подложка для прозрачных изображений, уменьшение и PNG. Изменённая подготовка растра использует новую версию ключа vision/OCR-кэша. Один document_tool/vision.py обслуживает все Qwen-VL запросы и кэш. Ограничения — 64 MiB, 40 миллионов пикселей на кадр, 200 кадров. Неподдержанные векторные форматы требуют экспорта в PNG/PDF. Прочтение встроенных картинок не считается полным просмотром слайда.

## Текст, исходный код и разметка

document_tool/text/read.py читает TXT/MD/JSON/XML/HTML/HTM/LOG/INI/YAML/TOML/PY/JS/TS/CSS/SQL/RST. read_text сохраняет пробелы, переводы строк и ведущие нули; длинная строка разбивается без потери символов. Метаданные включают кодировку, диапазон символов и строк. UTF-8 и BOM UTF-16/32 распознаются; предположенная старая кодировка вызывает предупреждение. Максимум 64 MiB. HTML/XML возвращаются исходным текстом без исполнения скриптов, сетевых загрузок или раскрытия внешних сущностей. Разбор DOM в браузере и создание/редактирование исходных файлов не добавлялись.

## Архивы

document_tool/archives/read.py предоставляет list_archive и open_archive_member. Манифест выдаётся с пагинацией; выбранный элемент сохраняется под хешем содержимого внутри DATA_ROOT/.archive-members. Имя из архива не используется как путь назначения. Ссылки, опасные/дублирующиеся имена и зашифрованные элементы отклоняются. Вложенные архивы в этом маршруте открываются явно. Индекс архива содержит только имена/размеры, а не текст документов внутри; это отмечено предупреждением.

ZIP читает стандартная библиотека, 7z — py7zr с ограниченным потоковым буфером без распаковки путей, RAR — rarfile с внешним unrar/bsdtar/совместимым backend. В Windows системный tar.exe используется как libarchive backend при отсутствии bsdtar. Наличие backend и качество реальных RAR ещё надо проверить в целевой сборке. Библиотеки добавлены в requirements и конфигурацию упаковки.

Лимиты: архив 512 MiB, до 10000 записей манифеста, файл до 64 MiB. Для solid 7z дополнительно проверяется общая заявленная распаковка до 512 MiB. Старый read_document сохраняет совместимость с маленькими архивами, но ограничен общим бюджетом 200 файлов/128 MiB/120000 символов и тремя уровнями; результат содержит пропуски и признак усечения. Большие архивы следует читать выборочно.

Потоковый API сверён с [py7zr](https://py7zr.readthedocs.io/en/latest/api.html) и [rarfile](https://rarfile.readthedocs.io/api.html).

## DOC, RTF, OpenDocument

document_tool/legacy/read.py содержит прежний путь DOC (antiword/catdoc, иначе Word piece table), striprtf для RTF и безопасное чтение content.xml для ODT/ODS/ODP. Объединённый текст режется общим индексом. У OpenDocument ограничены повторения строк/ячеек и запрещены DTD. Вёрстка, поля и встроенные изображения не восстанавливаются полностью — это явно отмечено. ODS здесь не полноценная редактируемая книга, формулы не пересчитываются. Запись в эти старые форматы не добавлялась.

## Open WebUI и проверки

Код Open WebUI не менялся. Для /process сохранено извлечение текста вложенных документов архивов и читаемое представление HTML/XML; это политика адаптера, которая вызывает те же обработчики, без копии парсеров. В отличие от upload, серверный индекс архива содержит манифест, а read_text возвращает исходную разметку. Серверный адаптер /process пользуется теми же читателями, сохраняет корректную единицу слайда/части, автоматически не вызывает визуальную модель или OCR отдельных изображений. RAG-индексация/эмбеддинги остаются в Open WebUI. DeepSeek получает текст/JSON от инструментов, без зависимости от нативных файловых API провайдеров.

На искусственных файлах проверены чтение/продолжение длинного UTF-16 текста, точное сохранение символов, разметка без выполнения, группы/таблицы/заметки PPTX, кэш vision с подменённым HTTP, TIFF с несколькими кадрами и crop, локальный OCR с подменённым движком, ZIP и выборочное чтение настоящего 7z без распаковки путей, ограничения ссылок/выхода из каталога, повторы OpenDocument и отказ от внешних XML-сущностей. Полный прогон на пользовательских документах, реальный RAR, LibreOffice, качество OCR/vision и desktop-сборка остаются отдельным этапом.

Обычный `python -m pytest` теперь собирает tests/ (ранее testpaths ошибочно указывал на app/). Для локального прогона без записи стандартного кэша: `python -m pytest -p no:cacheprovider`.
