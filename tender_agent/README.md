# Браузерный агент поиска закупок

Отдельный пакет `tender_agent`. Он получает задание на естественном языке, открывает площадку в Playwright, ищет закупки и возвращает структурированный результат. Цикл один: наблюдение, решение, действие, проверка.

В основном проекте агент работает отдельным контейнером `tender-agent` и отдаёт Open WebUI инструмент `POST /search_tenders` на порту 8010.

## Что делает текущая версия

- Разбирает задание в `TaskSpec`: адрес, ключевое слово, число результатов, сортировка по дате публикации, скачивание, лимиты.
- Слово «последние» означает наиболее позднюю подтверждённую дату публикации. Дата окончания приёма заявок этой датой не становится.
- Слово «мониторинг» означает одну проверку, а не фоновый процесс.
- Открывает страницу, определяет её тип по DOM и проходит поиск, сортировку и страницы.
- Для незнакомой страницы один раз спрашивает LLM. Без настроенной модели такая страница завершается ошибкой.
- Проверяет, что действие изменило страницу. Повтор одного и того же неудачного шага останавливает задачу.
- Скачивает файл только если задание этого просит, и проверяет, что файл лежит в рабочей папке и не пустой.
- Хранит в SQLite только проверенные подсказки профиля. Селектор, который больше ничего не находит в списке, отбрасывается.
- Не обходит авторизацию и CAPTCHA: задача останавливается со статусом `needs_user`.

## Установка

Нужен Python 3.10+. Образ tools-server собран на 3.10, локально пакет проверялся на 3.12.

```powershell
cd tender_agent
py -3 -m pip install -e ".[dev]"
py -3 -m playwright install chromium
```

Секреты задаются переменными окружения, образец — в `.env.example`. Файл `.env` в пакет не читается, пока его явно не подхватит окружение процесса.

## Запуск

```powershell
py -3 -m tender_agent "С площадки https://example.com верни последние пять закупок по ключевому слову ""сервер"""
```

Команда печатает JSON со статусом `completed`, `partial`, `needs_user` или `failed`.

Локальные и внутренние адреса отклоняются. Пустой `TENDER_AGENT_ALLOWED_HOSTS` разрешает публичные хосты. Непустой список ограничивает переходы этими доменами.

## Проверка

```powershell
py -3 -m pytest
```

Основной набор ходит только на локальные HTML-фикстуры через `tenders.example.test`. Внешние площадки в него не входят.

## Настройки по умолчанию

| Переменная | Значение |
| --- | --- |
| `TENDER_AGENT_MAX_ACTIONS` | 40 |
| `TENDER_AGENT_MAX_LLM_CALLS` | 12 |
| `TENDER_AGENT_MAX_RETRIES` | 2 |
| `TENDER_AGENT_TIMEOUT_SECONDS` | 120 |
| `TENDER_AGENT_MAX_PAGES` | 5 |
| `TENDER_AGENT_DEFAULT_LIMIT` | 5 |

Каталог данных — `data/tenders` в корне репозитория, тот же, что у остального проекта. База профилей лежит в `data/tenders/_agent`, скачанные файлы — в `data/tenders/_browser`. Папки с префиксом `_` дашборд не показывает как закупки. Путь в `.env` считается от корня репозитория.

## Ограничения

Размеченная выдача читается из `article.tender-card`, `tr.tender-row` и `main[data-tender-id]`. Если такой разметки нет, агент берёт ссылки, похожие на карточки закупки, но без даты публикации помечает их как требующие проверки, когда задание просит последние записи.

Совпадение с ключевым словом — это вхождение в название. Если поиск на сайте уже выполнен, а слова в названии нет, запись остаётся с пометкой `needs_review`, а не отбрасывается.

Модель нужна только как необязательный поставщик одного следующего действия. Визуальный разбор скриншотов подключается через `VisionProvider`, но в этом проходе агент его не вызывает.
