# Как работает tender_agent (состояние `main`, 40bbc23)

Разбор перед рефакторингом: основной цикл, эвристики, модель, зрение. Ссылки — на `tender_agent/src/tender_agent/`.

## 1. Общая схема задания

`agent/orchestrator.py: execute()`:

1. `parse_task` — из текста: площадка, ключевое слово, сколько записей, сортировка, качать ли документы.
2. Переход на стартовый адрес.
3. **Цикл по выдаче** (пока `actions < 40` и не вышло `timeout_seconds = 120`): наблюдение → решение → действие → проверка.
4. `rank_tenders` — склейка строк одной процедуры (лоты), сортировка, первые N.
5. **Чтение карточек** `_open_cards`: до 5 вкладок параллельно, каждая карточка — `_read_one_card`.
6. Статус (`completed / partial / failed / needs_user`), счётчики `stats.methods`, запись в БД.

## 2. Шаг цикла по выдаче

**Наблюдение** — `browser/observations.py: get_page_state()`: один JS-снимок страницы (элементы с `data-ta-ref`, карточки выдачи, пары «подпись — значение», основной текст). Затем эвристики:

- `heuristics/discovery.bind_controls` — находит поле поиска, кнопку «Найти», сортировку, «Далее», раздел документов, ссылки на файлы;
- `cards_from_blocks` / `fallback_cards` — карточки, если JS не нашёл их сразу;
- `classify` — тип страницы: `captcha / login / error / documents / tender_card / tender_list / empty / search / home / unknown`.

**Решение** — `heuristics/policy.py: decide()`, правила по порядку:

| # | Условие | Действие |
|---|---|---|
| 1 | вход / CAPTCHA | `ask_user` (стоп) |
| 2 | страница ошибки | `finish` |
| 3 | запрос не применён и есть поле поиска | `fill` (+ клик «Найти» или Enter) |
| 4 | нужна сортировка и есть кнопка | `click sort` |
| 5 | нужна сортировка и есть меню сортировки | `click sort_menu` |
| 6 | есть карточки, эту выдачу ещё не читали | `extract` |
| 7 | записей мало (или сортировка не подтверждена) и есть «Далее» | `click next` |
| 8 | главная без карточек, есть раздел «Закупки» | `click section` |
| 9 | незнакомая страница | `consult_llm` |
| 10 | иначе | `finish` |

**Перехваты в оркестраторе** (поверх `decide`, в самом `execute`):

- `consult_llm` → модель выбирает действие по 40 элементам (`planner.consult`); не выбрала → зрение;
- `finish`, а ничего не собрано → зрение;
- перед `extract`, если сортировка нужна, а не применена → известный URL сортировки (`known_sites`) → зрение → предупреждение «не подтверждена»;
- `fill` уже падал → известный URL поиска (`known_sites`);
- одно действие повторяется без изменения страницы (`max_retries = 2`) → зрение → стоп.

**Действие и проверка**: `extract` — модель дочитывает блоки выдачи (`refine`, до 3 раз), затем правила собирают карточки (`_absorb`). Остальное — `_act` (клик/ввод), затем проверка: страница изменилась, после поиска в выдаче есть слово запроса (`search_applied`).

## 3. Чтение карточки (`_read_one_card`)

1. Открыть в своей вкладке, подождать сеть (до 2,5 с), снимок.
2. **Правила**: поля по подписям (`apply_labeled_fields`).
3. **Модель — всегда**: `read_card` → цитаты/ид полей, лоты, `document_refs`, `documents_tab_ref`; всё сверяется со страницей (`apply_page_reading`).
4. Файлы: ссылки, которые видит код (`file_refs`), + выбор модели.
5. Файлов нет → раздел «Документы»: ссылку даёт модель, если нет — правило; клик, снимок, модель ещё раз (если код сам не увидел файлов).
6. Всё ещё нет → **зрение** с целью «открой раздел документов».
7. Скачивание, если просили.

## 4. Зрение (`agent/vision.py` → AI-vision)

- Включается `TENDER_AGENT_VISION_ENABLED=true`, библиотека `ai_vision` ставится в образ из соседнего репозитория.
- `VisionAgent(mode="planner", extract=False).run_on_page(та же вкладка, цель, max_steps=10)`: Qwen3-VL-plus смотрит на скриншот и решает, что делать, UI-TARS на d10 даёт координаты, клик делает Playwright в той же вкладке.
- Зрение только **доводит до нужного экрана** (выдача по запросу, сортировка, раздел документов). Данные не извлекает: после него снова снимок DOM и обычный цикл.
- Лимиты: в цикле — 2 вызова (`vision_max_calls`), на карточках — ещё 3 на всё задание (`vision_max_calls + 1`). Время зрения в цикле не съедает бюджет (`started += spent`), время на карточках не ограничено.

## 5. «Проверенные» знания о площадках

Их два источника, и они не связаны:

- `heuristics/known_sites.py` — статическая таблица: адрес поиска (ЕИС, Москва, ТЭК-Торг, Фабрикант, B2B-Center) и параметры сортировки (ЕИС, Москва, ТЭК-Торг, Росэлторг);
- профиль площадки в БД (`sites/profiles.py`, `storage/repository.py`): после успеха запоминаются placeholder поля поиска и общий селектор карточек; при следующем заходе селектор проверяется по числу карточек.

## 6. Что видно по коду и стоит отрефакторить

1. **Каскад «правило → модель → зрение» размазан.** Решение (`decide`) и запасные пути (6 мест в `execute`) живут отдельно; `execute` — ~320 строк из 695 в файле. Предлагаю один каскад на этап: `search`, `sort`, `next`, `documents` — у каждого упорядоченный список способов, каждый способ сам отмечает `methods`.
2. **Известный адрес идёт последним, хотя он самый дешёвый.** Для ЕИС и ТЭК-Торга сначала вводим запрос в поле, и только после неудачи — известный URL; сортировку тоже сначала ищем кнопкой. Для площадок из таблицы известный путь должен быть первым.
3. **Флаги вместо состояния этапа.** В `Progress` 9 флагов про поиск и сортировку (`keyword_applied`, `sort_applied`, `sort_verified`, `sort_fallback_done`, `sort_menu_opened`, `search_url_tried`, `site_sort_used`, `vision_check_pending`, `pending_search`), и их согласование разбросано по `execute`. Заменить на статус этапа: `pending / applied / verified / failed` и способ.
4. **Карточки не ограничены по времени.** Проверка таймаута — только перед захватом вкладки, все 5 карточек стартуют сразу, зрение на карточке до 10 шагов. Отсюда 206 с на Росэлторге при `timeout_seconds = 120`. Нужен общий бюджет на этап карточек и отказ от зрения, если на карточке нет ни раздела, ни признаков файлов.
5. **`_read_one_card` — 110 строк с вложенной функцией.** Разделить: `read_fields`, `find_documents` (каскад), `download`.
6. **Модель на карточке вызывается всегда**, даже если подписи уже дали все поля. Можно звать её, только если не хватает ключевых полей или документов (экономия 1 вызова на карточку).
7. **Два источника знаний о площадках** (п. 5) — объединить в один профиль: адрес поиска, сортировка, селектор карточек, подсказка про документы; статический + выученный.
8. Мелочи: пакет `sites/` остался из одного файла на 14 строк; у `_sync_flags` неиспользуемый параметр `sort_required`.
