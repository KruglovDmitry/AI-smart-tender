## A. Подсказки — сделано (ветка `site-notes`, f4dab83), проверка в понедельник 26.10

- Файл на площадку `tender-agent/src/tender_agent/sites/notes/<домен>.md`: шапка (`domain`, `also`, `updated`),
  разделы «Общее», «Выдача», «Карточка», «Ловушки» (с датой).
- Свой файл в `<data_dir>/_agent/sites/` с тем же доменом заменяет базовый.
- Модель получает `site_notes` в `next_action`: только сайт текущей страницы и текущий этап, до 1500 символов.
  Заметка — подсказка, при расхождении права страница.
- Заметки для 10 площадок по прогонам 21–23.10.
- Проверка: пересборка, Росатом и Сбер-АСТ «ИБП», сравнить шаги, вызовы и время с прогонами 23.10.

## B. Заметки из прогонов (следующий шаг)

Пользователь этого не видит и ничего не подтверждает: это внутренний механизм.

1. После прогона модель по трейсу предлагает дополнения к заметке (что сработало, ловушки).
   Они попадают в кандидаты (`_agent/sites/candidates/`), а не в заметку.
2. Кандидат становится заметкой автоматически, когда тот же вывод подтвердился в 2–3 удачных прогонах.
   Если с заметкой прогоны стали хуже (больше шагов, таймауты), она возвращается в кандидаты.
3. Мы собираем кандидатов с пробных установок и лучшие включаем в базовые заметки следующей сборки.
4. Ручное редактирование — только в скрытом разделе панели для нас; клиент его не видит.

## C. Кэш действий (после B)

- Удачная последовательность на площадке (закрыть обучение, сортировка, фильтр) запоминается по домену и этапу
  и в следующий раз повторяется без вызова модели.
- Элемент не найден или страница не та — управление возвращается модели, кэш обновляется по новому удачному шагу.
- Замерить экономию: вызовы модели, токены, время на площадку.
